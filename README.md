# Local Transcriber — المفرّغ المحلي

Private, offline video/audio transcription for Windows, built for **Arabic first**.
Select or drop a video → it is transcribed **on your PC** with faster-whisper → edit the
Arabic text → export a properly shaped, right-to-left **PDF**.

> **بالعربية باختصار:** تطبيق ويندوز يفرّغ الفيديو والصوت إلى نص محلياً بالكامل
> (faster-whisper + CTranslate2)، ويدعم العربية ولهجاتها، ويصدّر ملف PDF بخط عربي
> مضمَّن واتجاه من اليمين لليسار. التثبيت: `npm install` ثم التشغيل: `npm run dev`.
> لا مفاتيح API، ولا رفع لأي ملف، ويعمل دون إنترنت بعد تنزيل النموذج لأول مرة.

## Architecture

```
┌──────────────────────── Electron (Windows desktop shell) ───────────────────────┐
│                                                                                  │
│  Renderer: Next.js + React + TypeScript (static export, served via app://)       │
│    • drag & drop / file dialog → sends the *file path* only                      │
│    • polls job progress, shows live transcript, edits, exports                   │
│                         │  HTTP on 127.0.0.1:<random port> + per-launch token    │
│                         ▼                                                        │
│  Python backend (FastAPI) — started & supervised by Electron                     │
│    FFmpeg ──► 16 kHz mono PCM (audio stream only, temp file, memory-mapped)      │
│    faster-whisper / CTranslate2 ──► CUDA float16 or CPU int8, Silero VAD, batched│
│    Model store ──► models/<name>/ (downloaded once from Hugging Face, then offline)│
│    fpdf2 + HarfBuzz + Amiri font ──► Arabic-shaped RTL PDF                        │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**Why this design**

- **Electron** turns the Next.js UI into a real Windows application (installer, Start-menu
  shortcut, native file dialogs, drag & drop with real file paths) and owns the backend's
  lifecycle: it starts it, restarts it if it crashes, and stops it on exit.
- **Next.js is exported statically** (`output: "export"`) — there is no Node server at
  runtime; Electron serves the files through a private `app://` protocol with a strict
  Content-Security-Policy (`connect-src` allows only `127.0.0.1`).
- **Python is the natural home for faster-whisper/CTranslate2.** It runs as a separate
  process so heavy inference never blocks the UI; each transcription runs in a worker
  thread and the UI polls progress a few times per second.
- **Local-only IPC:** the backend binds `127.0.0.1` on a random port and requires a random
  token generated by Electron on every launch, so neither the network nor other programs
  or web pages on the same PC can use it.
- **Packaging:** the backend is frozen with PyInstaller and shipped inside the Electron
  installer (electron-builder, NSIS), together with a static FFmpeg build. End users don't
  install Python, FFmpeg or Node.

## Privacy

- Media files are **never uploaded**: the UI only passes a local file *path* to the local
  backend, which reads it from disk.
- Transcripts never leave the machine; PDFs are written to a local folder you choose.
- No API keys, accounts, analytics or telemetry (Hugging Face and Next.js telemetry are
  explicitly disabled).
- The **only** network access is downloading a Whisper model the first time you use it
  (from the public Hugging Face Hub, no account). After that the app works fully offline.

## Requirements

| Component | Version | Notes |
|-----------|---------|-------|
| Windows | 10 / 11, 64-bit | |
| Node.js | **22.12 or newer** (22 LTS / 24 LTS) | Required by Electron. `winget install OpenJS.NodeJS.LTS` |
| Python | 3.10 – 3.13 (3.12 recommended) | Only for development/building. `winget install Python.Python.3.12` |
| NVIDIA GPU | optional | Any CUDA-capable card with a recent driver (≥ 528). No CUDA Toolkit needed. |
| Disk | ~1 GB for dependencies + 0.1–3 GB per model | |

FFmpeg is **not** a manual prerequisite: `npm install` downloads a static build
(`ffmpeg-static`), and the packaged app ships it.

## Install

```bash
npm install
```

That single command:

1. installs the JavaScript tooling (Next.js, Electron, electron-builder, FFmpeg binary);
2. runs `scripts/setup-python.mjs` (npm `postinstall`), which
   - finds Python 3.10–3.13 (`py -3.12`, `py -3.11`, … or `python`; override with `PYTHON=`),
   - creates `backend/.venv` and installs `backend/requirements.txt`,
   - if `nvidia-smi` works, also installs NVIDIA's cuBLAS + cuDNN runtime wheels
     (`backend/requirements-gpu.txt`) so the GPU works without a CUDA Toolkit,
   - runs a self-check.

Re-running is instant when nothing changed. Useful variants:

```bash
npm run setup       # repair / re-run the Python setup
npm run setup:gpu   # force-install the NVIDIA CUDA/cuDNN runtime libraries
npm run setup:cpu   # CPU-only environment (smaller)
npm run doctor      # print a diagnostic report (Python, FFmpeg, GPU, models)
```

If Python isn't installed, `npm install` still completes and prints what to do; the app
also shows the same instructions on screen.

## Run in development

```bash
npm run dev
```

Starts the Next.js dev server (port 3123, hot reload), then Electron, which launches the
Python backend. Closing the window stops everything. Backend logs are written to
`%APPDATA%\Local Transcriber\logs\backend.log`.

Other scripts:

| Script | What it does |
|--------|--------------|
| `npm run build:ui` | Static export of the UI to `frontend/out` |
| `npm start` | Run Electron against the built UI (after `build:ui`) |
| `npm run typecheck` | TypeScript check of the frontend |

## Models

| Model | Download | Speed | Arabic accuracy | Notes |
|-------|----------|-------|-----------------|-------|
| tiny | 75 MB | ★★★★★ | ★ | Quick tests only |
| base | 145 MB | ★★★★★ | ★★ | Very weak PCs |
| small | 485 MB | ★★★★ | ★★★ | Low-end CPUs |
| medium | 1.5 GB | ★★ | ★★★★ | |
| **large-v3-turbo** | 1.6 GB | ★★★★ | ★★★★ | **Default on CPU** — near large-v3 accuracy, 4-layer decoder makes it much faster |
| **large-v3** | 3.1 GB | ★ | ★★★★★ | **Default on GPU** — best Arabic and dialect accuracy |

- **Download:** pick a model and press **Start** (it downloads automatically with a
  progress bar), or press **Download** next to it beforehand.
- **Storage:** `models/<name>/` in development; `%LOCALAPPDATA%\Local Transcriber\models`
  in the installed app. Use the "Models folder" link to open it.
- **Offline:** once a model shows **Downloaded**, it is loaded with `local_files_only=True`
  and no network access is attempted.
- **Delete:** trash icon next to the model (or delete its folder).
- **Pre-seeding an offline PC:** copy a model folder (including its `.complete` file) from
  another machine into the models folder.

**Priority presets**

| Preset | Decoder | When to use |
|--------|---------|-------------|
| Fastest | batched, greedy (beam 1) | Drafts, very long recordings |
| Balanced (default) | batched, beam 5, VAD silence skipping | Best speed/accuracy trade-off |
| Most accurate | sequential, beam 5, conditioned on previous text | Best punctuation/coherence for lectures |

"Improve Arabic punctuation" gives Whisper a short, well punctuated Arabic prompt so it
emits `،` `؟` `.` instead of long unpunctuated runs.

## Build & package the Windows app

Run on Windows (PyInstaller builds for the OS it runs on):

```bash
npm run dist
```

This runs:

1. `npm run build:ui` → `frontend/out` (static UI)
2. `npm run build:backend` → `backend/dist/transcriber-backend/` (PyInstaller one-folder
   build of the backend, including CTranslate2, the Silero VAD model, the Arabic font and —
   if installed — NVIDIA's CUDA/cuDNN DLLs)
3. `electron-builder --win` → `release/LocalTranscriber-Setup-<version>.exe` (NSIS installer)

`npm run pack` produces an unpacked app in `release/win-unpacked/` for quick testing.

**CPU-only vs GPU installer.** If the build machine has the NVIDIA runtime wheels
installed (automatic when it has an NVIDIA GPU), they are bundled (~+800 MB) so GPU
transcription works on end-user PCs that only have the NVIDIA driver. For a small
CPU-only installer, run `npm run setup:cpu` in a fresh clone (or delete `backend/.venv`
first) before `npm run dist`. Either build falls back to the CPU automatically.

The installed app keeps user data outside Program Files:
models in `%LOCALAPPDATA%\Local Transcriber\models`, PDFs in
`Documents\Local Transcriber`, logs in `%APPDATA%\Local Transcriber\logs`.

> Code signing is not configured. Unsigned installers trigger a SmartScreen warning; add
> your certificate via electron-builder's `win.certificateFile` / `CSC_LINK` for releases.

## GPU / CUDA troubleshooting

The app uses the GPU when **Device = Auto** (or GPU) and CUDA is really usable; otherwise
it uses the CPU. If the GPU fails while loading or running a model in Auto mode, the job is
retried on the CPU automatically and a notice is shown.

Check the state with `npm run doctor` (look at `cuda_available` and `cuda_reason`).

| Symptom | Fix |
|---------|-----|
| "No supported GPU" but you have an NVIDIA card | Update the NVIDIA driver (Studio or Game Ready, 528+). `nvidia-smi` must work in a terminal. |
| `CUDA 12 runtime libraries are missing: cublas64_12.dll …` | `npm run setup:gpu` (installs `nvidia-cublas-cu12` + `nvidia-cudnn-cu12` into the venv). |
| `Could not locate cudnn_ops64_9.dll` / cuDNN errors | Same: `npm run setup:gpu`. Remove old cuDNN 8 folders from `PATH` if you installed them manually. |
| Out of memory on GPU | Choose a smaller model (large-v3-turbo or medium), or the "Fastest" preset (smaller beam). |
| AMD / Intel GPU | CTranslate2 supports NVIDIA CUDA only; the CPU (int8) is used. |
| Entry-level GPU (e.g. GeForce MX110/MX130/MX150, 2 GB) | Detected automatically: with less than ~3.5 GB of VRAM or a pre-Pascal chip, **Auto uses the CPU**, which is faster and more stable on these cards. You can still pick GPU manually for tiny/base models. |
| `npm install` fails with `EBADENGINE` | Your Node.js is older than 22.12. Install Node 22 LTS, delete `node_modules`, run `npm install` again. |
| GPU works in dev but not in the installed app | Build the installer on a machine where `npm run setup:gpu` was run, so the DLLs are bundled. |

## Other troubleshooting

| Problem | Solution |
|---------|----------|
| "Python environment is not installed" | Install Python 3.12, then `npm run setup`. |
| "FFmpeg was not found" | `npm install` (re-downloads `ffmpeg-static`), or put `ffmpeg.exe` on `PATH`. |
| Model download failed | Needs internet the first time only. Behind a proxy set `HTTPS_PROXY`. Partial downloads resume. |
| "Not enough memory" | Close other apps or choose a smaller model; large-v3 on CPU needs ~4.5 GB free RAM. |
| "No speech was detected" | The file has no audible speech (music/silence) or the wrong audio track. |
| File is "corrupted" or "unsupported" | Re-download/re-encode the file; ensure it has an audio track. |
| PDF can't be saved | Close the PDF if it is open in a viewer and export again. |
| Anything else | See `%APPDATA%\Local Transcriber\logs\backend.log` and `npm run doctor`. |

## Performance notes

- **No video transcoding.** FFmpeg decodes only the audio stream (`-vn -sn -dn`) and
  resamples once, directly to 16 kHz mono PCM — the exact input Whisper needs.
- **Low, flat memory.** PCM is written to a temp file (~115 MB per hour) and memory-mapped;
  long recordings are processed in ~20-minute windows split at the quietest moment, so a
  3-hour video uses about as much RAM as a 20-minute one.
- **CTranslate2 quantization:** `float16` on NVIDIA GPUs, `int8` on CPUs (≈3–4× faster than
  float32 with minimal accuracy loss), CPU threads = physical cores.
- **Batched inference + VAD:** Silero VAD removes silence, and speech chunks are decoded in
  batches (16 on GPU / 8 on CPU, halved for large models).
- **Language detected once** on up to 5 minutes of speech, then fixed for the whole file
  (prevents language flips in long recordings).
- **Model stays loaded** between transcriptions; switching files doesn't reload it.
- **Hallucination guard:** drops well-known Whisper artefacts on silence (e.g. subtitle
  credits like "ترجمة نانسي قنقر") and breaks repetition loops.
